# Дашборд руководителя предприятия (1С:УНФ 3.0)

Дашборд для быстрой оценки состояния предприятия: деньги, выручка и прибыль,
дебиторская и кредиторская задолженность с просрочкой, запасы, портфель заказов.
Данные берутся из 1С:УНФ 3.0 через HTTP-сервис расширения, кэшируются бэкендом и
показываются в браузере.

```
Браузер ──> FastAPI ──> HTTP-сервис расширения 1С ──> регистры УНФ
```

Исходная задача и ограничения по стеку — `STACK.md` / `STACK-BRIEF.md`.
Правила проекта — `AGENT.md`. Что предстоит сделать — `TASKS.md`.

| Документ | О чём |
|---|---|
| `docs/API-КОНТРАКТ.md` | интерфейсы всех трёх частей — **читать первым** |
| `docs/РАСЧЁТ-ПОКАЗАТЕЛЕЙ.md` | формулы показателей и сознательные упрощения |
| `docs/ПАМЯТЬ-проекта.md` | состояние работ, проверенные команды, грабли |

## Состав

| Каталог | Что это |
|---|---|
| `unf_ext/` | расширение 1С `Dashboard` (XML-выгрузка, формат «Выгрузить в файлы») |
| `backend/` | FastAPI + SQLAlchemy + Alembic |
| `frontend/` | Vue 3 + Vite + Ant Design Vue |
| `tools/` | скрипты для 1С: загрузка расширения, проверка, сборка, публикация |
| `docs/` | документация проекта |
| `build/` | артефакты (`.cfe`, временные выгрузки) — вне git |

## Быстрый старт

### 1. Расширение 1С

Требуется установленная платформа 1С (проверено на 8.3.27.2214) и база УНФ 3.0,
в которой создано расширение `Dashboard`.

```powershell
cd D:\Developer\dashboard
.\tools\load-extension.ps1    # загрузить исходники в базу и применить к БД
.\tools\check-extension.ps1   # синтаксический контроль модулей
.\tools\build-extension.ps1   # собрать build\Dashboard.cfe
```

Параметры подключения по умолчанию: серверная база `localhost\novofon`, пользователь
`Администратор`, пустой пароль. Передаются параметрами `-Server`, `-User`, `-Password`.

**Важно:** загрузка конфигурации требует монопольного доступа к базе. Открытый сеанс 1С
заставляет Конфигуратор молча ждать — это выглядит как зависание (признак: процесс
`1cv8.exe` не грузит ЦП).

### 2. Публикация базы на веб-сервере

HTTP-сервис доступен только у опубликованной базы. **На этой машине база уже
опубликована** через Конфигуратор:

| Что | Адрес |
|---|---|
| Веб-клиент | `http://localhost:8080/novofon/ru/` |
| HTTP-сервис показателей | `http://localhost:8080/novofon/hs/dashboard` |

Проверка сервиса:

```powershell
.\tools\verify-kpi.ps1 -BaseUrl 'http://localhost:8080/novofon/hs/dashboard' -User 'Администратор' -Password ''
```

Для другой машины публикацию можно создать скриптом (отдельный сайт IIS на порту 8090,
сервис по адресу `/unf`) — из консоли, запущенной **от имени администратора**:

```powershell
.\tools\publish-base.ps1
```

Скрипт на живой машине не проверялся: публикацию сделали вручную. Пользователю 1С, под
которым публикуется база, нужна роль расширения `D_ОсновнаяРоль` и права на чтение
регистров из ролей основной конфигурации (в демо-базе это `Администратор`).

### 3. Бэкенд

```powershell
cd backend
uv sync
Copy-Item ..\.env.example .env     # заполнить ONE_C_USER, ONE_C_PASSWORD, JWT_SECRET
uv run alembic upgrade head
uv run python -m app.cli seed-demo # пользователь rukovoditel / dashboard (только для разработки)
uv run uvicorn app.main:app --reload --port 8000
```

Проверка: `http://localhost:8000/api/v1/health`, документация — `/docs`.

### 4. Фронтенд

```powershell
cd frontend
pnpm install
pnpm dev            # http://localhost:5173, запросы к /api проксируются на :8000
```

Вход — пользователем, созданным в бэкенде.

## Разработка

- Правки расширения — только в `unf_ext/`, затем `load-extension.ps1`. Файлы обязаны быть
  в UTF-8 **с BOM** и с переводами строк **CRLF** — скрипт приводит их к этому виду сам,
  но при правке сторонним редактором проверяйте.
- Структурная проверка модулей без запуска 1С — через MCP-сервер `mcp_1c`
  (инструмент `check`); он же даёт поиск по всей типовой УНФ.
- Типы фронтенда генерируются из `openapi.json`: `pnpm api:types`.

## Особенности окружения

- Платформа 1С: `C:\Program Files\1cv8\8.3.27.2214\bin\1cv8.exe`.
- База разработки: серверная, `localhost\novofon` (УНФ 3.0.12.261).
- Справочная выгрузка типовой УНФ: `D:\unf_conf` (только чтение).
- Порт 8080 занят IIS, поэтому публикация — на 8090.
- Docker не установлен: `docker-compose.yml` и `Dockerfile` лежат в репозитории, но
  локально не проверяются.
- PostgreSQL-инстанс 1С (`pgsql-17.2-4.1C-x64`) относится к серверу 1С — не трогать.
