# Правила проекта: дашборд руководителя для УНФ 3.0

Дашборд для быстрой оценки состояния предприятия: деньги, выручка и прибыль,
дебиторская и кредиторская задолженность с просрочкой, запасы, портфель заказов.
Данные берутся из 1С:УНФ 3.0 через HTTP-сервис расширения, кэшируются бэкендом и
показываются в браузере.

Все три части связаны одним документом — **[docs/API-КОНТРАКТ.md](docs/API-КОНТРАКТ.md)**.
Читать его до любой правки.

```
Браузер ──(1)──> FastAPI ──(2)──> HTTP-сервис расширения 1С ──> регистры УНФ
        /api/v1/*         /hs/dashboard/*
```

**1** API бэкенда: JWT, refresh в `httpOnly` cookie, кэш снимков показателей.
**2** API расширения `D_DashboardApi`: HTTP Basic 1С, только чтение, только GET.

## Стек

Работаем строго по **STACK-BRIEF.md** (обоснования — в `STACK.md`).
Python 3.14 + FastAPI + SQLAlchemy 2.1 (async) + Alembic, SQLite локально и PostgreSQL 17
на стенде; Vue 3 `<script setup>` + TypeScript 5.9.3 + Vite + Pinia + Ant Design Vue +
TanStack Vue Query; `uv` и `pnpm`, всё через `uv run`.

Расхождения, которые пришлось допустить осознанно:

- **`dayjs` 1.11** добавлен напрямую — нужен для русской локали `a-date-picker`, в стеке
  не назван. Плюс `@types/node`.
- **Библиотеки графиков нет** — столбцы и линия нарисованы своими SVG-компонентами
  (`BarChart.vue`, `LineChart.vue`). Добавлять chart-библиотеку только вместе со стеком.
- **Ant Design Vue регистрируется по списку** используемых компонентов в
  `frontend/src/app/plugins.ts`, а не целиком: новый тег `a-*` обязательно дописать туда,
  иначе тест падает с «Компонент не зарегистрирован».

## Железные правила

### Общие

1. **Контракт API — единственный источник истины.** Меняешь ответ — сначала правишь
   `docs/API-КОНТРАКТ.md`, потом все три стороны. Дрейф контракта — дефект.
2. **Дашборд никогда не пишет в 1С.** Только чтение.
3. **Пустая база — не ошибка.** Все блоки обязаны отдаваться нулями, а не падать:
   дашборд могут открыть на только что развёрнутой базе.
4. **Секреты** (пароль пользователя 1С, `JWT_SECRET`) — только в `.env`, в репозиторий не
   попадают. `JWT_SECRET` короче 32 байт недопустим, проверяется на старте.
5. **Свежесть данных важнее скорости**: показываем `fetchedAt`, `ageSeconds`, `stale`,
   и только потом оптимизируем.

### Расширение 1С: файлы и загрузка

6. Исходники — `unf_ext`, формат выгрузки **иерархический**, кодировка **UTF-8 с BOM**,
   переводы строк **CRLF**. Скрипты нормализуют формат сами (`Convert-DumpEncoding`
   в `tools\1c-common.ps1`).
7. `Configuration.xml` обязан совпадать с файлами на диске: объект, лежащий в каталоге, но
   не объявленный в `<ChildObjects>`, при загрузке будет **удалён** вместе с перестройкой
   командного интерфейса. После каждой загрузки сверяйте исходники с базой
   (`/DumpConfigToFiles` во временный каталог и сравнение) — кроме служебного
   `ConfigDumpInfo.xml`, расхождений быть не должно.
8. Заимствованные объекты (`ObjectBelonging = Adopted`) — правим только модули в `Ext\`.
9. Типовые объекты не копировать: пишем свои запросы, опираясь на разбор типовой логики
   в `docs/РАСЧЁТ-ПОКАЗАТЕЛЕЙ.md`.
10. После каждой правки модуля — `mcp_1c` → `check` (структурная проверка), затем
    `/CheckModules -Extension` на загруженной базе. Обе проверки ловят разное: первая
    знает про неизвестные процедуры и аргументы, вторая компилирует модули платформой.

### Расширение 1С: контракты платформы (найденные на практике)

11. **Обработчик HTTP-сервиса объявляется ровно с одним параметром:**
    `Функция healthGET(Запрос)`. Метод без параметра ломает привязку **всего** модуля, и
    сервис отвечает `500` с текстом «Ошибка инициализации модуля: <Расширение>
    HTTPСервис.<Имя>.Модуль». Текст ошибки виден только в теле HTTP-ответа: `curl -i`.
12. **Одна раскладка в именах.** Модуль объявлен как `D_Показатели` — латинская `D`.
    Кириллическая `Д` в вызове даёт ту же ошибку инициализации, а `/CheckModules` и
    структурная проверка `mcp_1c` её **не видят**. Проверка кодов символов:
    `($s.ToCharArray() | ForEach-Object { [int]$_ }) -join ' '` (латинская `D` = 68,
    кириллическая `Д` = 1044).
13. **Привилегированные общие модули в расширении запрещены**: `UpdateDBCfg` падает с
    кодом 101 и текстом «Использование привилегированных общих модулей в расширении
    недопустимо».
14. **Роль расширения не может выдать права на объекты основной конфигурации** — 1С молча
    отбрасывает такие записи при загрузке. Роль расширения несёт права только на объекты
    расширения (методы HTTP-сервиса, `Use`); чтение регистров разрешают роли основной
    конфигурации. В демо-базе это `Администратор`.
15. **В условии виртуальной таблицы** (`Остатки(...)`, `Обороты(...)`):
    ресурсы называются как в регистре (`Сумма`, а не `СуммаОстаток`); **реквизиты регистра
    недоступны вовсе** — дату отгрузки берём из документа
    (`Заказы.ЗаказПокупателя.ДатаОтгрузки`); проверки ресурсов пишем в `ГДЕ` внешнего
    запроса (`И Расчеты.СуммаОстаток > 0`).
16. **Агрегат по пустой выборке возвращает `NULL`**, а не `Неопределено`. Проверять оба
    случая: `Окр(NULL, 2)` падает с «Преобразование значения к типу Число не может быть
    выполнено». В модуле это делает `НольЕслиПусто`.
17. **`ЕстьNULL` — функция языка запросов, не BSL.** В BSL для результатов запроса нужен
    свой помощник.
18. **`НачалоНедели` принимает только дату** (второго параметра «начало недели» в 8.3.27
    нет); неделя определяется региональными настройками (для русской локали — понедельник).
19. **Расписание регламентного задания** живёт рядом с объектом —
    `ScheduledJobs\<Имя>\Ext\Schedule.xml`; в XML самого объекта расписания нет. Задание
    `D_СамопроверкаПоказателей` оставлено **выключенным** (`<Use>false</Use>`) и без
    расписания, чтобы на боевой базе ничего не запускалось само.

### Расширение 1С: команды и окружение

20. **`1cv8.exe` — GUI-приложение, PowerShell его не ждёт.** Через `& $v8 DESIGNER ...`
    команда возвращается мгновенно с пустым кодом, а Конфигуратор работает в фоне. Нужен
    `Start-Process -Wait -PassThru`; так сделано в `Invoke-1CDesigner`.
21. **Режим `DESIGNER` обязателен и идёт первым аргументом** — иначе «Неопределен режим
    запуска».
22. **Пустой пароль нельзя передать пустым элементом массива**: `Start-Process` склеивает
    аргументы в строку, элемент исчезает, и следующим аргументом становится `/OUT`.
    Пустой пароль передаётся как литерал `""`.
23. **Сообщения платформы читаются только из файла `/OUT`** — в stdout они не попадают.
24. **Загрузка конфигурации требует монопольного доступа.** Открытый Конфигуратор или
    сеанс заставляют её ждать либо падать с «Ошибка блокировки информационной базы».
    Признак зависания — `1cv8.exe` почти не грузит ЦП. **Не убивать процессы `1cv8`
    вслепую**: сначала выяснять по `CommandLine`, чей он (в этой сессии так был найден
    Конфигуратор пользователя с демонстрационной базой).
25. **`mcp_1c` не видит новые файлы до повторного `open`** — иначе «файл отсутствует
    в источниках».
26. **`rac` этой версии не умеет публикации** (в справке только `cluster` и `infobase`).
    Службу администрирования при необходимости поднимать отдельным процессом:
    `ras.exe cluster --port=1545`.

### Бэкенд

27. Слои: роутер → сервис → модель. Роутер не содержит бизнес-логики и не ходит во внешние
    системы — только через `app/integrations/`.
28. Диалект-нейтральные типы: `Uuid`, `Enum`, `JSON` — не `postgresql.UUID`, не `JSONB`.
    Alembic в batch-режиме (`render_as_batch=True`).
29. **`render_item` в Alembic обязан возвращать `False`**, а не `None`: с `None` Alembic
    считает результат готовым текстом, и миграция создаёт **пустые** `create_table`.
30. **SQLAlchemy 2.1 не подменяет `BIGINT` на `INTEGER` в SQLite** — `BIGINT PRIMARY KEY`
    не автоинкрементится. Для первичных ключей есть `PK_BIGINT` с
    `with_variant(Integer(), "sqlite")` в `app/db/types.py`.
31. **FastAPI ищет cookie по имени параметра**: параметр с refresh-токеном обязан иметь
    `Cookie(alias=REFRESH_COOKIE_NAME)`, иначе всегда приходит `None`.
32. **Из моделей убран `from __future__ import annotations`**: SQLAlchemy 2.1 не разбирает
    отложенные аннотации `Mapped[...]` и создаёт таблицы без колонок.
33. Деньги — **целые копейки** в базе, `Decimal` на границе, наружу (в JSON) — число рублей
    с копейками.
34. Обмен с 1С — только в `app/integrations/one_c.py`. Таймауты обязательны, ошибки 1С
    превращаются в `503 kpi_unavailable` с понятным текстом, а не в 500.
35. **`httpx` обязан ходить к 1С с `trust_env=False`** (настройка `ONE_C_TRUST_ENV=false`).
    На Windows httpx берёт прокси не только из переменных окружения, но и из системных
    настроек (реестра): при включённом системном прокси запрос к локальной публикации 1С
    уходит через прокси, и приходит `503` с пустым телом **без заголовка `Server`** —
    то есть отвечает прокси, а не 1С. Признак: `curl` к тому же адресу отвечает `200`.
36. **Схемы ответов «мягкие»** (у полей есть значения по умолчанию), чтобы частичный ответ
    1С не превращался в ошибку валидации. Поэтому в `openapi.json` поля блоков
    необязательные, хотя в ответе они есть всегда; на фронтенде полная форма объявлена
    типом `Complete<T>` в `frontend/src/api/dashboard.ts`.

### Фронтенд

37. **Типы API генерируются из `openapi.json`** (`pnpm api:types`), руками не пишутся.
    Имена схем сопоставлены с доменными именами в одном файле —
    `frontend/src/api/dashboard.ts` (таблица `Schemas[...]`), чтобы перегенерация не
    задевала экраны и компоненты.
38. Проверка типов — `pnpm typecheck` (`vue-tsc`), не `tsc`: обычный `tsc` не заглядывает
    в `.vue` и молча пропускает ошибки в шаблонах.
39. Access-токен только в памяти, refresh — в `httpOnly` cookie; в `localStorage` токенов
    нет.
40. Один origin: в разработке прокси Vite, на стенде nginx. CORS не нужен.
41. Шрифты self-hosted, внешних CDN нет.

## Команды

Стенд целиком:

```powershell
.\tools\start-all.ps1    # проверит 1С, применит миграции, поднимет бэкенд и фронтенд, напечатает адреса
.\tools\stop-all.ps1     # остановит бэкенд и фронтенд (публикацию 1С не трогает)
```

Расширение 1С:

```powershell
.\tools\load-extension.ps1    # LoadConfigFromFiles + UpdateDBCfg (нужен монопольный доступ)
.\tools\check-extension.ps1   # CheckModules -Extension
.\tools\build-extension.ps1   # DumpCfg → build\Dashboard.cfe
.\tools\publish-base.ps1      # веб-публикация базы (нужны права администратора, не проверен)
.\tools\verify-kpi.ps1 -BaseUrl 'http://localhost:8080/novofon/hs/dashboard' -User 'Администратор' -Password ''
.\tools\kpi-probe-listener.ps1  # приёмник отчёта самопроверки, если публикации нет
```

Бэкенд (из `backend/`): `uv sync`, `uv run alembic upgrade head`,
`uv run python -m app.cli seed-demo`, `uv run uvicorn app.main:app --port 8000`,
`uv run ruff check --fix . && uv run ruff format .`, `uv run ty check`, `uv run pytest`,
`uv run python -m app.openapi`.

Фронтенд (из `frontend/`): `pnpm install`, `pnpm dev`, `pnpm typecheck`, `pnpm lint`,
`pnpm test`, `pnpm build`, `pnpm api:types`.

## Приёмка

1. `tools\verify-kpi.ps1` — 16 проверок HTTP-сервиса: доступность, список организаций,
   сводка, сходимость сумм (деньги = счета + касса, сумма корзин = итог дебиторки,
   рентабельность = прибыль / выручка), 12 месяцев динамики без пропусков,
   детализация по контрагентам, отказ на недопустимый период с кодом 400.
2. `uv run pytest` в `backend/` — 95 тестов; `pnpm test` в `frontend/` — 49 тестов.
3. Сквозной сценарий: `http://localhost:5173` → вход → все блоки с данными.

**Особенность демо-базы:** продаж в ней почти нет (единственная ненулевая выручка —
250 ₽ в апреле 2024), поэтому блок продаж и график показывают нули и «данных за период
нет». Это содержимое базы, а не ошибка: запрос проверен и возвращает реальные записи
регистра. Остальные шесть блоков наполнены. Сверку сумм с типовыми отчётами («Анализ
бизнеса», «Пульс бизнеса», «Реестр старения дебиторской задолженности») на базе с
продажами ещё предстоит сделать.
