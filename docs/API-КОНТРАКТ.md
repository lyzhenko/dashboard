# Контракт API: дашборд руководителя на УНФ 3.0

Документ описывает **все** интерфейсы проекта и связи между ними. Это единственный
источник истины: расширение 1С, бэкенд и фронтенд обязаны следовать ему без отклонений.
Формулы показателей и их обоснование — в `docs/РАСЧЁТ-ПОКАЗАТЕЛЕЙ.md`.

```
Браузер ──(1)──> FastAPI ──(2)──> Расширение 1С (HTTP-сервис) ──> регистры УНФ
          /api/v1/*        /hs/dashboard/*
```

1. **API расширения 1С** — то, что опрашивает бэкенд. HTTP-сервис `D_DashboardApi`,
   корневой URL `dashboard`, базовая аутентификация 1С. Только чтение, только GET.
2. **API бэкенда** — то, что видит браузер. Авторизация JWT, префикс `/api/v1`.

## Соглашения о значениях

- **Деньги** — числа в рублях с двумя знаками (JSON number). Внутри бэкенда — целые
  копейки (`int`), `Decimal` на границе. Копейки по сети не передаются.
- **В ответах расширения 1С нет `null`.** Отсутствие данных выражается нулём, пустым
  массивом или пустой строкой. Проценты равны `0`, если базы сравнения нет; чтобы
  отличить «ноль процентов» от «нет базы», рядом всегда есть исходные суммы.
- **`null` допустим только в API бэкенда**, где его формирует Python (например,
  `organization: null` означает «все организации»).
- **Даты** — строки `ГГГГ-ММ-ДД`; месяц — `ГГГГ-ММ`; момент времени — `ГГГГ-ММ-ДДTЧЧ:ММ:СС`
  без часового пояса, как отдаёт 1С (время сервера 1С).

## 1. API расширения 1С (для бэкенда)

База: `<публикация>/hs/dashboard`, например `http://localhost:8090/unf/hs/dashboard`.
Публикация создаётся скриптом `tools/publish-base.ps1` (каталог `/unf`, порт 8090).

Аутентификация: HTTP Basic, пользователь 1С с ролью `D_ОсновнаяРоль`.
Неверные учётные данные → `401`. Нет права на метод → `403`.

Все ответы — `application/json; charset=utf-8`. Ошибка — соответствующий код HTTP и тело:

```json
{"error": {"code": "bad_request", "message": "Параметр period имеет недопустимое значение: \"decade\". Допустимо: day, week, month, quarter, year."}}
```

Коды ошибок: `bad_request` (400), `unauthorized` (401), `forbidden` (403),
`not_found` (404), `internal` (500).

### 1.1. `GET /health`

Проверка доступности. Данные не читает.

```json
{
  "status": "ok",
  "service": "D_DashboardApi",
  "version": "1.0.0",
  "configuration": "УправлениеНебольшойФирмой 3.0.12.261",
  "serverTime": "2026-10-11T07:40:00"
}
```

### 1.2. `GET /organizations`

Список организаций для выбора на дашборде. Отсортирован по наименованию.

```json
{
  "items": [
    {"id": "0a1b2c3d-1111-2222-3333-444455556666", "name": "ООО «Ромашка»", "inn": "7701234567", "isDefault": false}
  ]
}
```

`isDefault = true` только у единственной организации в базе. Если организаций несколько,
флаг не выставлен ни у одной — дашборд по умолчанию показывает **все организации**.

### 1.3. `GET /kpi`

Сводка для главного экрана. Параметры:

| Параметр | Обязательный | По умолчанию | Значение |
|---|---|---|---|
| `date` | нет | текущая дата сервера | дата, **на которую** считаются остатки |
| `period` | нет | `month` | период оборота продаж: `day`, `week`, `month`, `quarter`, `year` |
| `organization` | нет | все организации | идентификатор организации |

**Границы периода.** Период начинается с календарной границы, содержащей `date`, и
заканчивается самой датой `date`: `month` — с 1-го числа месяца, `week` — с понедельника,
`quarter` — с начала квартала, `year` — с 1 января, `day` — сама дата.

**Предыдущий период** — та же календарная единица назад, и внутри неё то же смещение
даты от начала: 1–11 октября сравнивается с 1–11 сентября (а не с целым сентябрём),
11 октября 2026 — с 11 октября 2025.

```json
{
  "generatedAt": "2026-10-11T07:40:00",
  "asOf": "2026-10-11",
  "period": {
    "kind": "month",
    "from": "2026-10-01", "to": "2026-10-11",
    "prevFrom": "2026-09-01", "prevTo": "2026-09-11"
  },
  "organization": {"id": "0a1b...666", "name": "ООО «Ромашка»"},
  "money": {
    "total": 1234567.89,
    "accounts": 1000000.00,
    "cash": 234567.89,
    "currency": "RUB"
  },
  "sales": {
    "revenue": 500000.00,
    "revenuePrev": 450000.00,
    "revenueDeltaPct": 11.11,
    "revenueNet": 416666.67,
    "grossProfit": 120000.00,
    "grossProfitPrev": 90000.00,
    "marginPct": 24.00,
    "documents": 42,
    "avgTicket": 11904.76
  },
  "receivables": {
    "total": 800000.00,
    "overdue": 150000.00,
    "overduePct": 18.75,
    "buckets": [
      {"label": "0–7 дней", "amount": 650000.00},
      {"label": "8–14 дней", "amount": 50000.00},
      {"label": "15–30 дней", "amount": 60000.00},
      {"label": "31–60 дней", "amount": 30000.00},
      {"label": "Свыше 60 дней", "amount": 10000.00}
    ]
  },
  "payables": {
    "total": 500000.00,
    "overdue": 70000.00,
    "overduePct": 14.00,
    "buckets": [
      {"label": "0–7 дней", "amount": 300000.00},
      {"label": "8–14 дней", "amount": 100000.00},
      {"label": "15–30 дней", "amount": 50000.00},
      {"label": "31–60 дней", "amount": 40000.00},
      {"label": "Свыше 60 дней", "amount": 10000.00}
    ]
  },
  "stock": {
    "total": 3000000.00,
    "skuCount": 1520,
    "negativeCount": 0
  },
  "orders": {
    "portfolio": 900000.00,
    "count": 37,
    "positions": 128.500,
    "overdueCount": 4,
    "overdueAmount": 120000.00,
    "dueThisWeek": 250000.00,
    "orderedAmount": 900000.00,
    "paidAmount": 600000.00
  },
  "topDebtors": [
    {"name": "ООО «Василёк»", "amount": 300000.00, "overdue": 100000.00, "maxOverdueDays": 45}
  ],
  "topSuppliers": [
    {"name": "ООО «Поставщик»", "amount": 200000.00, "overdue": 0, "maxOverdueDays": 0}
  ]
}
```

Правила и смысл полей:

- `money.total` = `accounts` + `cash`; `accounts` — безналичные, `cash` — наличные
  (перечисление `ТипыДенежныхСредств`). Валюта — валюта управленческого учёта.
- `sales.revenue` — выручка **с НДС**, как её считает сама УНФ; `revenueNet` — без НДС.
  `grossProfit` = выручка − себестоимость; `marginPct` = прибыль / выручка × 100.
  `revenueDeltaPct` = (выручка − выручка прошлого периода) / выручка прошлого периода × 100,
  при нулевой прошлой выручке — `0`.
- `documents` — число документов продаж за период (`ЗакрытиеМесяца` не считается:
  это корректировка себестоимости, а не продажа). `avgTicket` = выручка / документов.
- `receivables.buckets` / `payables.buckets` — **возраст долга** от даты расчётного
  документа до даты отчёта, интервалы как в типовой УНФ: 0–7, 8–14, 15–30, 31–60, свыше 60.
- `overdue` — **просроченная** часть: долг, возраст которого превысил срок оплаты по
  договору (`СрокОплатыПокупателя`). Просрочка и возраст — разные вещи: долг возрастом
  10 дней при сроке оплаты 30 дней не просрочен. Просрочка не входит в отдельную корзину,
  она «размазана» по корзинам возраста.
- `overduePct` = `overdue` / `total` × 100, при нулевом итоге — `0`.
- `stock.total` — стоимость запасов на дату; `skuCount` — число номенклатур с ненулевым
  остатком; `negativeCount` — число номенклатур с отрицательным остатком (признак
  ошибок в учёте).
- `orders.portfolio` — сумма открытых (не отгруженных) заказов покупателей;
  `count` — их количество; `positions` — количество единиц к отгрузке;
  `overdueCount` / `overdueAmount` — заказы с датой отгрузки раньше даты отчёта;
  `dueThisWeek` — сумма к отгрузке в ближайшие 7 дней от даты отчёта;
  `orderedAmount` / `paidAmount` — заказы и оплаты по ним, зарегистрированные за период.
- `topDebtors` / `topSuppliers` — по 5 записей, отсортированы по сумме убыв.
- Все блоки присутствуют всегда; на пустой базе возвращаются нули и пустые массивы.

### 1.4. `GET /dynamics`

Выручка, валовая прибыль и рентабельность по месяцам — для графика.

| Параметр | Обязательный | По умолчанию | Значение |
|---|---|---|---|
| `months` | нет | `12` | сколько последних месяцев вернуть (1–36) |
| `date` | нет | текущая дата | последний месяц периода |
| `organization` | нет | все | идентификатор организации |

```json
{
  "items": [
    {"month": "2025-11", "revenue": 420000.00, "grossProfit": 98000.00, "marginPct": 23.33}
  ]
}
```

Месяцы идут по возрастанию, без пропусков: месяцы без продаж возвращаются нулями,
поэтому график всегда содержит ровно `months` точек. Последний месяц — месяц даты `date`
и обычно неполный.

### 1.5. `GET /debtors`

Детализация задолженности по контрагентам — для перехода с карточки на список.

| Параметр | Обязательный | По умолчанию | Значение |
|---|---|---|---|
| `kind` | нет | `receivable` | `receivable` — нам должны, `payable` — мы должны |
| `limit` | нет | `10` | сколько контрагентов вернуть (1–100) |
| `date` | нет | текущая дата | дата остатков |
| `organization` | нет | все | идентификатор организации |

```json
{
  "kind": "receivable",
  "asOf": "2026-10-11",
  "total": 800000.00,
  "overdue": 150000.00,
  "items": [
    {
      "name": "ООО «Василёк»",
      "amount": 300000.00,
      "overdue": 100000.00,
      "maxOverdueDays": 45,
      "buckets": [
        {"label": "0–7 дней", "amount": 200000.00},
        {"label": "31–60 дней", "amount": 100000.00}
      ]
    }
  ]
}
```

`maxOverdueDays` — максимальная просрочка по контрагенту в днях, `0` если просрочки нет.

## 2. API бэкенда (для фронтенда)

База `/api/v1`. Все ответы — JSON. Ошибка:

```json
{"detail": {"code": "kpi_unavailable", "message": "Данные 1С недоступны: превышено время ожидания"}}
```

Коды: `unauthorized` (401), `forbidden` (403), `not_found` (404),
`validation_error` (422), `kpi_unavailable` (503).

### 2.1. Авторизация

| Метод | Путь | Тело / результат |
|---|---|---|
| `POST` | `/auth/login` | `{"username": "...", "password": "..."}` → `{"accessToken": "...", "expiresIn": 900, "user": {...}}`, refresh-токен в `httpOnly` cookie |
| `POST` | `/auth/refresh` | без тела (cookie) → `{"accessToken": "...", "expiresIn": 900}` |
| `POST` | `/auth/logout` | очищает cookie |
| `GET` | `/auth/me` | `{"id": 1, "username": "rukovoditel", "fullName": "Иванов И. И.", "roles": ["viewer"]}` |

Access-токен — только в памяти фронтенда, refresh — только в `httpOnly` cookie.
Правило стека: в `localStorage` токенов нет.

### 2.2. Данные дашборда

| Метод | Путь | Результат |
|---|---|---|
| `GET` | `/dashboard/summary?date=&period=&organization=` | блоки из 1.3 плюс `meta` |
| `GET` | `/dashboard/dynamics?months=&organization=` | `{"items": [...]}` — как в 1.4 |
| `GET` | `/dashboard/debtors?kind=&limit=&organization=` | как в 1.5 |
| `GET` | `/dashboard/organizations` | как в 1.2 |
| `POST` | `/dashboard/refresh` | принудительно перечитать из 1С, вернуть `summary` |

Тело ответа `/dashboard/summary` совпадает с `/kpi`, но дополнено блоком `meta` и
допускает `organization: null` для «все организации»:

```json
{
  "meta": {
    "source": "1c",
    "fetchedAt": "2026-10-11T07:40:03",
    "ageSeconds": 42,
    "stale": false,
    "cached": true
  },
  "...": "остальные блоки как в 1.3"
}
```

`stale = true`, если данные старше `KPI_CACHE_TTL_SECONDS`. Фронтенд показывает плашку
«данные устарели» и кнопку обновления.

### 2.3. Служебное

| Метод | Путь | Результат |
|---|---|---|
| `GET` | `/health` | `{"status": "ok", "database": "ok", "oneC": "ok"\|"unavailable"}` |

## 3. Соответствие блоков и источников в УНФ

| Блок | Источник в УНФ |
|---|---|
| `money` | `РегистрНакопления.ДенежныеСредства`, остатки, деление по `ТипДенежныхСредств` |
| `sales` | `РегистрНакопления.Продажи`, обороты; себестоимость — ресурс `Себестоимость` |
| `receivables` | `РегистрНакопления.РасчетыСПокупателями`, остатки, `ТипРасчетов = Долг` |
| `payables` | `РегистрНакопления.РасчетыСПоставщиками`, остатки, `ТипРасчетов = Долг` |
| `stock` | `РегистрНакопления.Запасы`, остатки, `СчетУчета.ТипСчета = Запасы` |
| `orders` | `РегистрНакопления.ЗаказыПокупателей` (портфель) и `ОплатаСчетовИЗаказов` (за период) |
| `topDebtors` / `topSuppliers` | те же регистры расчётов, свёртка по контрагенту |

Точные формулы, поля и принятые упрощения — в `docs/РАСЧЁТ-ПОКАЗАТЕЛЕЙ.md`.

## 4. Правила, обязательные для всех трёх сторон

1. **Только чтение.** Ни один вызов не меняет данные в 1С.
2. **Никаких «магических» строк.** Имена параметров и полей JSON — ровно как здесь.
3. **Пустое значение — не ошибка.** Нет данных → нули, пустые массивы. Дашборд не должен
   падать на пустой базе.
4. **Округление денег** — до копеек на стороне 1С; бэкенд не переокругляет.
5. **Период всегда возвращается в ответе** (`period`) — фронтенд показывает его
   пользователю, чтобы не было двусмысленности «за какой период цифра».
6. **Свежесть данных видна пользователю**: `meta.fetchedAt`, `meta.stale`, `meta.ageSeconds`.
