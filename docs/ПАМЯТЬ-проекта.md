## Грабли: 1С

1. **`1cv8.exe` — GUI-приложение, PowerShell его не ждёт.** Через `& $v8 DESIGNER ...`
   команда возвращается мгновенно с пустым кодом, а Конфигуратор работает в фоне.
   Нужен `Start-Process -Wait -PassThru` (так сделано в `tools\1c-common.ps1`).
2. **Режим `DESIGNER` обязателен и идёт первым** — без него «Неопределен режим запуска».
3. **Пустой пароль нельзя передать пустым элементом массива**: `Start-Process` склеивает
   аргументы в строку, элемент исчезает, и следующим аргументом становится `/OUT`.
   Пустой пароль передаётся как литерал `""`.
4. **Сообщения платформы читаются только из файла `/OUT`** — в stdout они не попадают.
5. **Загрузка конфигурации требует монопольного доступа.** Открытый Конфигуратор или
   сеанс заставляют её молча ждать либо падать с «Ошибка блокировки информационной базы».
   Признак зависания — `1cv8.exe` не грузит ЦП. **Не убивать процессы `1cv8` вслепую:**
   сначала выяснить по `CommandLine`, чей он (в этой сессии так был найден Конфигуратор
   пользователя с базой `Управление нашей фирмой (демонстрационная база) #1`).
6. **Формат файлов выгрузки — UTF-8 с BOM и CRLF.** Ручная правка ломает сравнение с
   базой; скрипты нормализуют формат сами (`Convert-DumpEncoding`).
7. **`mcp_1c` не видит новые файлы до повторного `open`** — иначе «файл отсутствует в источниках».
8. **`rac` этой версии не умеет публикации** (только `cluster` и `infobase`). Службу
   администрирования при необходимости поднимать как `ras.exe cluster --port=1545`.
9. **`НачалоНедели` принимает только дату** (второго параметра «начало недели» в 8.3.27 нет).
10. **`ЕстьNULL` — функция языка запросов, не BSL.** Агрегат по пустой выборке возвращает
    **`NULL`** (а не `Неопределено`), поэтому проверять нужно оба: `Окр(NULL, 2)` падает
    с «Преобразование значения к типу Число не может быть выполнено».
11. **В условии виртуальной таблицы доступны только измерения и ресурсы регистра, и
    называются они как в регистре** (`Сумма`, а не `СуммаОстаток`). Проверки ресурсов —
    только в `ГДЕ` внешнего запроса (`И Расчеты.СуммаОстаток > 0`).
12. **Реквизиты регистра в виртуальных таблицах недоступны.** `ДатаОтгрузки` у
    `ЗаказыПокупателей` — реквизит, поэтому дата отгрузки берётся из документа:
    `Заказы.ЗаказПокупателя.ДатаОтгрузки`.
13. **Обработчик HTTP-сервиса обязан иметь ровно один параметр (`Запрос`).** Метод без
    параметра ломает привязку всего модуля: сервис отвечает `500` с текстом
    «Ошибка инициализации модуля: <Расширение> HTTPСервис.<Имя>.Модуль». Диагностика —
    через `curl -i`: 1С пишет причину в тело ответа, а не только в журнал.
14. **Кириллические и латинские двойники в именах — источник «Ошибки инициализации
    модуля».** Модуль объявлен как `D_Показатели` (латинская `D`, код 68), а вызовы были
    `Д_Показатели` (кириллическая `Д`, код 1044). `/CheckModules` и структурная проверка
    `mcp_1c` этого не ловят. Проверять коды символов:
    `($text.ToCharArray() | % { [int]$_ }) -join ' '`.
15. **Привилегированные общие модули в расширении запрещены**: `UpdateDBCfg` падает с
    кодом 101 и текстом «Использование привилегированных общих модулей в расширении
    недопустимо».
16. **Роль расширения не может выдать права на объекты основной конфигурации** — 1С
    молча отбрасывает такие записи при загрузке (проверено сверкой `Rights.xml` с базой).
    Роль расширения несёт только права на объекты расширения (методы HTTP-сервиса);
    права на чтение регистров дают роли основной конфигурации. В демо-базе это
    `Администратор`.
17. **Расписание регламентного задания лежит рядом с объектом** — `ScheduledJobs\<Имя>\Ext\Schedule.xml`;
    в самом XML объекта расписания нет. Задание самопроверки оставлено выключенным
    (`<Use>false</Use>`) и без расписания, чтобы ничего не запускалось само.

## Грабли: бэкенд и окружение

18. **httpx на Windows берёт прокси не только из переменных окружения, но и из системных
    настроек (реестра).** При включённом системном прокси (`http://127.0.0.1:10809` на этой
    машине) запрос к локальной публикации 1С уходит через прокси, и приходит `503` с пустым
    телом **без заголовка `Server`** — то есть отвечает прокси, а не 1С. Лечится
    `trust_env=False` (настройка `ONE_C_TRUST_ENV=false`, по умолчанию выключено).
    Признак: `curl` к тому же адресу отвечает `200`.
19. **Пути в .NET-вызовах не зависят от `Set-Location`** — `[IO.File]::ReadAllText('src\...')`
    разрешается от исходного рабочего каталога процесса. Использовать абсолютные пути.
20. **`SummaryResponse.model_validate(payload)` опирается на значения по умолчанию** в
    схемах: так частичный ответ 1С не превращается в ошибку валидации. Поэтому в
    `openapi.json` поля блоков необязательные, хотя в ответе они есть всегда — на
    фронтенде полная форма объявлена типом `Complete<T>` в `src/api/dashboard.ts`.
